# v2.4.0 - RELEASE NOTES

Release Date: 2026-10-06

## Overview

**Music Box v2.4.0** is the second major stable release (versionCode 52,
package `com.example.juke`). It consolidates everything since v2.0.0-stable —
including the v2.1.x–v2.3.5-beta cycle and the shared phone/Alexa playback work —
into an update-compatible, signed, optimized stable APK.

## 🚀 Highlights Since v2.0.0-stable

### Shared Playback & Queue Ownership

- Coordinated phone ↔ Alexa output ownership with fenced handoffs, lease
  deadlines, and stale-poll protection.
- Queue identities preserved across handoffs; phone queue cursor recovered
  after remote reorder or restart.
- Remote playback sync centralized; downloads persisted in Room with
  transaction rollback coverage.
- Scoped audio credentials and authenticated phone queue writes.

### Playback & Downloads

- LRU streaming cache with seamless stream promotion and eviction protection.
- Dual download sources (Spotmate ↔ Gamepvz) with automatic fallback on
  errors or duration mismatch; 30-second previews and wrong-length audio
  rejected and re-routed.
- Queue-aware Spotmate recovery: immediate provider fallback plus deferred
  task polling when pipelines are backlogged.
- Resumable Spotify playlist imports that survive app close and network loss.

### Lyrics, Search & Library

- Three-stage lyrics fallback: LRCLib → YouTube Music lyrics → YouTube
  captions, with mini-player stale-lyric filtering and ±12s sync offset.
- Split search architecture: debounced YouTube Music autocomplete while
  typing, full Spotify metadata only on submit; multi-tap Search tab
  behavior and scroll-to-dismiss keyboard.
- Unified downloaded-collection pages with offline support, public playlist
  share IDs preserved, queue tools (shuffle upcoming, sort A–Z, clear
  played, save as playlist).

### Audio & UI

- In-pipeline volume/bass boost with stable AGC, edge-only skip silence,
  playback speed, 10-band equalizer, sleep timer, call handling.
- Liquid-glass UI revamp (player, search, library), tablet layouts,
  animated queue drag with optimistic moves, Power Tools diagnostics.

## 🔒 Stable Release Engineering

- Signed `release` variant: minified, resource-shrunk, non-debuggable, with
  R8 mapping preserved for crash decoding.
- Explicit signing configuration pins the installed app's certificate:
  missing or changed keys **fail the build** instead of shipping an APK
  that would force an uninstall.
- Diagnostic/HTTP logging disabled in release builds (`SafeLog` only emits
  errors outside debug).
- In-app updater points at `arookiecoder-ip/MusicBox-APP`: stable installs
  ignore prereleases, beta installs can upgrade to stable, and releases
  without an APK asset are skipped.
- `scripts/verify_release_apk.py` gates publishing: stable version format,
  package identity, signing certificate, non-debuggable flag, and SHA-256
  checksums.

## ✅ Validation

- Release JVM unit tests pass in CI (`testReleaseUnitTest`, including the
  `ReleasePolicyTest` channel-upgrade suite).
- Push builds green on the release branch; signed-APK verification and
  checksum publishing run in the `stable_release=true` workflow dispatch.

## ⬆️ Upgrading

- Updates from any APK signed with the pinned Music Box certificate install
  cleanly (versionCode 52 is newer than all previous releases).
- Installations from pre-stable-signing builds that used disposable
  runner-generated keys require **one final reinstall**; all subsequent
  updates then work normally.
- Keep the `feat/alexa-backend` branch until the signing key is backed up in
  the `ANDROID_DEBUG_KEYSTORE_BASE64` repository secret — the current key
  lives in that branch's Actions cache.
